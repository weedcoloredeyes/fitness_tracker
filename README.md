# Fitness Tracker · Telegram Mini App

Личный фитнес-трекер: цели по весу и проценту жира, календарь, отметки тренировок и ходьбы, месячная цель и индекс формы. Интерфейс работает внутри Telegram. Само приложение, API, бот и SQLite-база запускаются на вашем компьютере.

Основная инструкция ниже описывает локальный запуск. Отдельный раздел про webhook подходит для VPS с готовым публичным HTTPS-адресом; настройка самого VPS в неё не входит.

## замеры по дням

- главная показывает вес и процент жира только за сегодня в часовом поясе устройства. если замер не записан, поле остается пустым с небольшим напоминанием. цели и прогресс по последнему известному весу сохраняются.
- при открытии даты в календаре доступны и отметки активности, и замер этого дня. прошлые дни можно просматривать и исправлять; будущие замеры недоступны для записи. стрелки календаря открывают предыдущие и следующие 12 недель.
- раздел «индекс» содержит историю замеров: график записанного веса и таблицу веса/жира по датам. пропущенные дни не заполняются автоматически.
- схема sqlite v7 добавляет `daily_measurements` и дату начала расчета прогресса. показатели старой версии сохраняются отдельно как «прежний замер без даты»: старая схема не записывала дату измерения. исходные профили, цели, baseline и отметки при миграции не очищаются.
- старт новой цели привязан к исходному замеру: исправление его веса исправляет и старт, а не засчитывается как похудение. при удалении исходного веса старт берется из первого оставшегося замера начиная с даты начала цели. старые старты без даты сохраняются без догадок; смена цели начинает новый расчет по последнему известному весу.
- перед обновлением рабочей версии нужна согласованная резервная копия sqlite. файл базы сохраняется при обновлении кода.

## настраиваемые отметки и месячный план

- локальная версия использует схему sqlite v8. новые аккаунты начинают с двух отметок: «физ нагрузка» и «кардио». названия и список отметок свои для каждого пользователя; отметки архивируются с возможностью вернуть их, без удаления истории.
- внутри каждой категории доли равны: физ нагрузка дает максимум 50%, кардио — еще 50%. три выполненные отметки одной категории дают ровно 50%; дроби в расчете не округляются. интерфейс округляет только отображаемые значения.
- создание или архивация действует с текущей даты в часовом поясе пользователя. состав прошлых дней сохраняется, поэтому новые отметки не уменьшают прошлый результат. переименование меняет только подпись прежнего идентификатора.
- месячный индекс использует календарный месяц. полный набор отметок одной категории за день дает один день плана, часть — дробный зачет. для каждой категории задается своя цель; ее вклад равен `50 × min(зачтенные дни / цель, 1)`. общий индекс доступен после задания обеих целей. будущие дни не участвуют.
- старые пользователи, цели, замеры и отметки сохраняются без изменений в исходных таблицах. старые отметки также доступны в новом календаре; «микро» остается в исторических днях и архиве. прежняя цель тренировок становится целью физ нагрузки, цель кардио пользователь задает отдельно.
- упражнения вводятся в выбранном дне вручную: название, повторения, подходы и необязательный вес. дневник можно заполнить копированием последней тренировки; копия становится черновиком до сохранения. запись упражнений сама по себе не отмечает выполнение нагрузки.
- новые маршруты: `/api/tracking/definitions`, `/api/tracking/day`, `/api/tracking/calendar`, `/api/tracking/month`, `/api/tracking/goals`, `/api/workouts`, `/api/workouts/latest`. требуются обычная авторизация и параметр `timezone`; даты и месяц передаются отдельно. старые маршруты чтения отметок и недельного индекса сохранены для совместимости, новый интерфейс их не использует.
- после обновления полностью закройте миниаппку и откройте ее снова. официальный сервер отклоняет старый `PATCH /api/activity` ответом `409` до чтения тела и любых изменений базы: открытый старый клиент получит просьбу обновиться, а его отметки не попадут в отдельное устаревшее хранилище.

## Что понадобится

- **Node.js 24.x** — рекомендуемая версия. Минимум для проекта — 22.13. Проверка: `node --version` и `npm --version`. Скачать: [nodejs.org](https://nodejs.org/en/download).
- **Git** для клонирования: [git-scm.com](https://git-scm.com/downloads). Для приватного репозитория нужен доступ к нему и авторизация в GitHub, например через GitHub Desktop или настроенные SSH/HTTPS-учётные данные.
- **Telegram** и токен своего бота из [@BotFather](https://t.me/BotFather) — для входа, изменения и сохранения данных.
- **cloudflared** — для открытия локального приложения внутри Telegram по временному HTTPS-адресу. Для простого просмотра интерфейса в браузере он не нужен.
- Интернет: Telegram API, Web App SDK и HTTPS-туннель используют внешние сервисы.

SQLite включена в Node.js: отдельно устанавливать базу данных не нужно. Все команды выполняются из папки проекта, кроме установки инструментов и клонирования.

## 1. Скачать проект и установить зависимости

В Terminal на macOS или PowerShell на Windows:

```sh
git clone https://github.com/weedcoloredeyes/fitness_tracker.git
cd fitness_tracker
npm ci
```

`npm ci` устанавливает версии из `package-lock.json`. `node_modules/` появится локально и не хранится в Git.

Если `git clone` не проходит из-за авторизации, войдите в GitHub Desktop и клонируйте репозиторий через него, затем откройте терминал в полученной папке. Пароль от GitHub не является токеном бота.

Если в PowerShell запрещён запуск `npm.ps1`, используйте `npm.cmd` вместо `npm` или откройте обычную командную строку. Например: `npm.cmd ci`.

## 2. Создать локальный файл настроек

macOS / Linux:

```sh
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Если `.env` уже есть, **не перезаписывайте его**. Откройте файл любым текстовым редактором. На Windows убедитесь, что он называется `.env`, а не `.env.txt`.

```dotenv
BOT_TOKEN=
WEB_APP_URL=
```

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен вашего Telegram-бота, полученный у BotFather. Нужен API-серверу для проверки входа и процессу бота. |
| `WEB_APP_URL` | Публичный HTTPS-адрес туннеля из шага 5. Пока можно оставить пустым: серверу он не нужен. |
| `PORT` | Необязательный порт API-сервера. По умолчанию `5173`. |

Токен хранится только локально. Не добавляйте к секретам префикс `VITE_`: такие переменные могут попадать в интерфейс. `.env` и база данных исключены из Git.

Для создания нового бота откройте BotFather, отправьте `/newbot`, задайте имя и username, затем скопируйте выданный токен в `BOT_TOKEN`. Для запуска уже существующего бота используйте его токен. Одновременно должен работать только один процесс получения обновлений для одного токена.

## Полноценное локальное приложение без Telegram и туннеля

Для работы с существующим профилем прямо в браузере добавьте в локальный `.env`:

```dotenv
LOCAL_MODE=1
LOCAL_USER_ID=ЧИСЛОВОЙ_ID_СУЩЕСТВУЮЩЕГО_ПОЛЬЗОВАТЕЛЯ
PORT=5174
WEB_APP_URL=
```

`LOCAL_USER_ID` должен соответствовать существующей записи в таблице `users` базы `data/fitness.sqlite`. Сервер завершит запуск при ошибочном ID, чтобы не подменять сохранённые данные новым пустым профилем.

Затем выполните `npm run build` и `npm run server`, откройте `http://127.0.0.1:5174`. Можно менять показатели, цели и отметки; данные сохраняются в той же SQLite-базе. Бот, токен Telegram, Telegram SDK и Cloudflare для этого режима не нужны. Не запускайте `npm run bot` и туннель.

Локальный сервер принимает запросы только с этого компьютера и выдаёт браузеру локальную сессию. Чужие адреса, запросы через туннель и запросы без сессии отклоняются. После перезапуска сервера обновите страницу. Для возвращения к Telegram-режиму уберите `LOCAL_MODE=1` и перезапустите сервер.

## 3. Быстрый просмотр интерфейса в браузере

Если пока нужно только посмотреть экраны:

```sh
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Остановить — `Ctrl+C`.

Этот режим позволяет увидеть интерфейс, календарь и переключать вкладки. Он **не подменяет вход через Telegram**: персональные данные и сохранение без подписанного Telegram `initData` недоступны. Бот, токен и туннель для просмотра не нужны.

Перед следующим шагом остановите этот процесс: он использует тот же порт, что и сервер собранного приложения.

## 4. Собрать и запустить приложение на компьютере

Заполните `BOT_TOKEN` в `.env`, затем выполните:

```sh
npm run build
npm run server
```

Ожидаемая строка:

```text
Сервер: http://127.0.0.1:5173
```

**Оставьте этот терминал открытым.** Сервер раздаёт интерфейс из `dist/` и обрабатывает `/api/*`. Первый запуск создаст папку `data/` и SQLite-базу. Адрес в браузере тот же, но для работы с аккаунтом нужно открыть приложение через Telegram.

Сервер слушает только `127.0.0.1`. Он не открывает порт домашнего роутера и не предоставляет доступ по локальному IP телефона. Доступ с телефона в текущей настройке даёт HTTPS-туннель из следующего шага.

## 5. Подключить временный HTTPS-туннель

Telegram Mini App требует HTTPS-адрес. `localhost` на телефоне означает сам телефон, поэтому напрямую адрес вашего компьютера через него недоступен. Туннель направляет HTTPS-запросы к приложению на компьютере; сервер и база остаются локальными.

### Установить cloudflared

macOS, если уже установлен Homebrew:

```sh
brew install cloudflared
```

Без Homebrew можно скачать подходящий бинарный файл для macOS, а на Windows — установщик или исполняемый файл из [официальной инструкции Cloudflare](https://developers.cloudflare.com/tunnel/downloads/).

На Windows, если скачан отдельный `.exe`, переименуйте его в `cloudflared.exe` и положите, например, в `C:\Tools\cloudflared\`. Затем используйте полный путь к нему или добавьте папку в `PATH`.

### Запустить туннель

Во **втором терминале**, пока `npm run server` работает:

```sh
cloudflared tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:5173
```

Для Windows без настройки `PATH` та же команда выглядит так:

```powershell
& 'C:\Tools\cloudflared\cloudflared.exe' tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:5173
```

`http2` выбран для сетей, в которых блокируется QUIC/UDP. Для Quick Tunnel не нужны аккаунт Cloudflare и собственный домен. В терминале появится адрес вида:

```text
https://some-random-name.trycloudflare.com
```

Скопируйте **реальный выданный адрес** в `.env`:

```dotenv
WEB_APP_URL=https://some-random-name.trycloudflare.com
```

**Оставьте второй терминал открытым.** При новом запуске туннеля адрес меняется. Туннель временно делает интерфейс доступным из интернета всем, кто знает ссылку; персональные API требуют проверенного входа Telegram. Никогда не направляйте туннель на папку с `.env` или базой: используйте только наш API-сервер.

Документация: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## 6. Запустить Telegram-бота

В **третьем терминале** перейдите в папку проекта:

```sh
npm run bot
```

Ожидаемая строка:

```text
Бот запущен.
```

Бот установит постоянную кнопку меню «Открыть приложение». Откройте чат **с тем ботом, чей токен записан в `.env`**, отправьте `/start` и нажмите новую кнопку открытия.

Всё, что нужно оставить работающим для полноценного локального теста:

| Терминал | Процесс | Зачем |
| --- | --- | --- |
| 1 | `npm run server` | Интерфейс, API, работа с SQLite |
| 2 | `cloudflared tunnel ...` | HTTPS-доступ с телефона и Telegram |
| 3 | `npm run bot` | `/start` и настройка кнопки запуска |

На телефоне не обязательно быть в той же Wi-Fi-сети: в этом режиме используется публичный адрес туннеля. Если компьютер выключится, уснёт или потеряет интернет, приложение станет недоступно. Отключённый экран сам по себе не мешает; важен именно сон компьютера.

### Необязательно: большая кнопка запуска в профиле бота

В BotFather выберите своего бота через `/mybots`, найдите настройку **Main Mini App / Configure Mini App**, включите её и укажите текущий `WEB_APP_URL`. Названия пунктов зависят от интерфейса BotFather. После этого доступна кнопка запуска в профиле и ссылка вида `https://t.me/USERNAME_ВАШЕГО_БОТА?startapp`.

При смене адреса туннеля обновите его и в BotFather. Поле ввода текста в чате скрыть средствами Bot API нельзя; обычные текстовые сообщения наш бот не обрабатывает.

## Webhook на VPS без исходящего доступа к Telegram

По умолчанию бот использует polling. Чтобы принимать обновления входящими HTTPS-запросами, добавьте в существующий `.env` (не перезаписывая токен и остальные настройки):

```dotenv
BOT_TRANSPORT=webhook
WEBHOOK_PORT=8081
WEBHOOK_SECRET=СЛУЧАЙНЫЙ_СЕКРЕТ
BOT_INFO_FILE=data/bot-info.json
```

`WEB_APP_URL` должен содержать действующий публичный HTTPS-адрес Mini App, `LOCAL_MODE` — `0` или отсутствовать. `WEBHOOK_SECRET` обязателен: от 1 до 256 символов `A–Z`, `a–z`, `0–9`, `_`, `-`; используйте длинное случайное значение. Не публикуйте его и токен бота.

С компьютера, имеющего доступ к Telegram Bot API, заранее получите `getMe` для этого же токена и сохраните полный успешный JSON-ответ либо его поле `result` в `data/bot-info.json` на VPS. Файл должен содержать `id`, `is_bot: true`, `first_name`, `username`; `id` обязан совпадать с числом перед двоеточием в токене. Этот файл не заменяет SQLite-базу; API его не использует. Бот должен иметь право читать файл.

Запуск остаётся прежним: `npm run bot`. Вместо polling процесс слушает **только `127.0.0.1:8081`**, принимает **`POST /telegram/webhook`**. Опубликуйте этот единственный путь через HTTPS reverse proxy на `http://127.0.0.1:8081`, сохранив URI, тело запроса и заголовок `X-Telegram-Bot-Api-Secret-Token`. Остальные пути приложения по-прежнему направляются на API-порт 5173. Для webhook-пути в nginx рекомендуется `client_max_body_size 1m`; порт 8081 наружу не открывается. Например, внутри уже настроенного HTTPS `server`:

```nginx
location = /telegram/webhook {
    client_max_body_size 1m;
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Затем с компьютера, имеющего доступ к Telegram, выполните `setWebhook`: URL — публичный `https://ВАШ_АДРЕС/telegram/webhook`, `secret_token` — **точно тот же `WEBHOOK_SECRET`**. Отдельно настройте кнопку меню через Bot API `setChatMenuButton` или BotFather. Эти операции выполняются один раз при настройке; webhook-процесс на VPS сам их не вызывает. Одновременно polling для того же токена должен быть остановлен. Для возвращения к polling сначала удалите webhook через `deleteWebhook` с доступного компьютера, затем уберите `BOT_TRANSPORT=webhook` и перезапустите бота.

В этом режиме процесс не вызывает `getMe`, `setChatMenuButton` и `getUpdates` и запрещает исходящие HTTP-вызовы Bot API. `/start` возвращает единственный `sendMessage` прямо в HTTP-ответе Telegram, вместе с кнопкой `WEB_APP_URL`. Неверный или отсутствующий секрет отклоняет встроенный adapter grammY с кодом 401. При `SIGINT`/`SIGTERM` бот прекращает приём новых запросов и даёт текущим до 25 секунд на завершение.

У webhook reply есть ограничение: Telegram не возвращает боту результат отправки сообщения, поэтому такой ответ сам по себе не подтверждает доставку пользователю. Обычные сообщения и неизвестные обновления просто подтверждаются пустым HTTP 200. При смене токена обновите также `bot-info.json` и регистрацию webhook.

Источники: [grammY: webhooks](https://grammy.dev/guide/deployment-types#webhooks), [BotConfig.botInfo](https://grammy.dev/ref/core/botconfig#botinfo), [webhookCallback](https://grammy.dev/ref/core/webhookcallback), [ответ Bot API через webhook](https://core.telegram.org/bots/api#making-requests-when-getting-updates).

## Повторный запуск и остановка

При следующих запусках зависимости ставить заново не нужно, если проект не обновлялся:

1. `npm run server` в первом терминале.
2. Запустить туннель во втором.
3. Обновить `WEB_APP_URL` в `.env` новым адресом.
4. `npm run bot` в третьем.
5. Отправить `/start` и использовать **новую** кнопку: кнопки в старых сообщениях могут вести на старый туннель.

Остановить процессы можно `Ctrl+C` в каждом терминале. Если меняли только `WEB_APP_URL`, перезапустите бота; API-серверу этот адрес не нужен. Если меняли `BOT_TOKEN`, перезапустите и сервер, и бота.

## Обновление проекта

Остановите сервер и бота. В папке проекта:

```sh
git pull --ff-only
npm ci
npm run build
npm run server
```

Затем запустите туннель и бота по инструкции выше. Если локально изменены исходники, сохраните изменения перед `git pull`; не используйте принудительный сброс. Файлы `.env` и `data/` не перезаписываются обновлением из Git.

После изменения интерфейса нужен `npm run build`: обычный сервер читает `dist/`, а не исходники `src/`. После изменения API или бота перезапустите соответствующий процесс. После обновления полностью закройте и откройте Mini App.

## Режим разработки с автоматическим обновлением интерфейса

Для изменений кода запустите API и Vite в отдельных терминалах.

macOS / Linux, первый терминал:

```sh
PORT=5174 npm run server
```

Windows PowerShell, первый терминал:

```powershell
$env:PORT = '5174'
npm run server
```

Второй терминал, любая ОС:

```sh
npm run dev
```

Vite работает на `127.0.0.1:5173` и перенаправляет `/api` на `127.0.0.1:5174`. Для просмотра в браузере этого достаточно.

Для проверки этого режима внутри Telegram нужен туннель к порту Vite и **конкретный доверенный hostname** туннеля в `server.allowedHosts` в `vite.config.ts`:

```ts
server: {
  allowedHosts: ['your-actual-host.trycloudflare.com'],
  proxy: { '/api': 'http://127.0.0.1:5174' },
},
```

Не ставьте `allowedHosts: true`. При смене туннеля обновите hostname. Более простой путь проверки в Telegram — сборка и обычный сервер из шагов 4–6. `npm run preview` показывает статическую сборку без API и не подходит для полноценной проверки входа и сохранения.

## База, перенос и резервная копия

База создаётся автоматически: `data/fitness.sqlite`. В ней хранятся:

- `users` — Telegram ID, профиль пользователя и время входов;
- `app_settings` — закреплённый ID администратора;
- `daily_activity` — галочки отдельно для пользователя и даты;
- `body_profiles` — вес, процент жира и цели;
- `monthly_workout_goals` — цель по тренировкам отдельно на каждый месяц.

Для резервной копии **остановите API-сервер** и скопируйте `data/fitness.sqlite` в надёжное место. Для переноса на другой компьютер:

1. Установите проект и зависимости на новом компьютере.
2. Создайте `.env` и внесите токен своего бота.
3. До запуска сервера создайте `data/` и положите туда скопированный `fitness.sqlite`.
4. Соберите приложение и запустите его по инструкции.

Не удаляйте базу при обновлении. Схема обновляется автоматически. Старый `data/users.json`, если он существует, импортируется один раз в транзакции и остаётся резервной копией; действующее хранилище после переноса — SQLite. В Git не отправляются ни база, ни старый JSON, ни `.env`.

## Вход и администратор

API проверяет подпись Telegram `initData` токеном бота. Данные старше часа отклоняются: в таком случае переоткройте Mini App. Клиентский `initDataUnsafe` не используется для авторизации.

В текущем проекте первый подтверждённый вход **`@NotTofu`** закрепляет его числовой Telegram ID как администратора. После этого смена username не передаёт права другому аккаунту. Остальные получают роль пользователя. Для переноса уже закреплённых прав переносите базу; новый пустой файл не содержит старой привязки.

Проверка ролей и административный API списка пользователей реализованы; отдельного видимого раздела администрирования в текущем интерфейсе нет.

## Как считаются показатели

- **Главная**: текущие и целевые вес/процент жира вводятся числами. Первый вес становится стартовым; смена целевого веса начинает новый прогресс от текущего. Прогресс работает для снижения и набора веса.
- **Тренировки за месяц**: основная, микро или обе за один день дают **один зачёт**. Ходьба не считается тренировкой. Отдельные значения «Основные» и «Микро» могут пересекаться по дням. Цель задаётся на конкретный календарный месяц.
- **Календарь**: нажатие на день открывает «Тренировку» с выбранной датой. Фиолетовая полоска — основная, жёлтая — микро, бирюзовая — ходьба. Сегодня выделено рамкой.
- **Тренировка**: три независимые галочки, запись в фоне. При ошибке сохранения отметка откатывается. Ходьба означает выполнение минимум 8000 шагов; автоматического счётчика шагов нет.
- **Старый API индекса формы (`/api/form-index`)**: последние семь календарных дней, включая сегодня. В новом интерфейсе заменен месячным индексом из раздела выше. `ИФ = 50/7 × (О + 0,5М) + 50/7 × Х`, где О — дни с основной, М — с микро, Х — дни с ходьбой. В этой формуле основная и микро учитываются каждая со своим коэффициентом. Итог округляется до целого и ограничивается 100. Пример: 4 основных, 2 микро и 6 дней ходьбы → 79/100. Будущие даты не участвуют.

Часовой пояс берётся с устройства. Вкладки сохраняют данные в памяти, обновляются в фоне; индекс формы реагирует на галочки сразу. Сворачивание свайпом по содержимому отключено в поддерживаемых версиях Telegram, но жест по системной шапке остаётся под управлением Telegram.

## Проверки и команды

```sh
npm run typecheck
npm test
npm run build
```

Тесты используют временные базы и тестовые токены, не обращаются к вашему боту и не меняют рабочую базу.

| Команда | Действие |
| --- | --- |
| `npm ci` | Установка зависимостей по lock-файлу |
| `npm run dev` | Интерфейс Vite для разработки |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run server` | Интерфейс из `dist/` и API на одном порту |
| `npm run bot` | Telegram-бот и настройка кнопки запуска |
| `npm run typecheck` | Проверка типов всего проекта |
| `npm test` | Автоматические проверки API, базы и расчётов |
| `npm run preview` | Только статический просмотр сборки |

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `node` или `npm` не найден | Установить Node.js и открыть новый терминал. |
| Ошибка загрузки `node:sqlite` | Проверить версию Node.js; использовать рекомендованную 24.x. |
| Ошибка чтения `.env` | Создать файл в корне проекта, проверить расширение и текущую папку терминала. |
| Сервер не стартует / порт занят | Остановить другой Vite или сервер на 5173. Либо задать другой `PORT` и тот же порт в адресе туннеля. |
| Открывается старый интерфейс | Выполнить `npm run build`, полностью переоткрыть Mini App. |
| В браузере не работают галочки | Открыть приложение кнопкой в Telegram: браузер не передаёт подписанный вход. |
| Бот отвечает, Mini App зависает | Проверить URL туннеля в обычном браузере, работу сервера и cloudflared; сравнить с VPN и без него. |
| Старые кнопки не открывают приложение | Обновить `.env`, перезапустить бота, отправить `/start` заново. |
| «Открой приложение заново через Telegram» | Сессия старше часа, другой токен или запуск вне Telegram. Полностью переоткрыть приложение. |
| Бот не запускается | Проверить обе переменные `.env`, корректность токена и HTTPS-адрес. |
| Конфликт получения обновлений | Остановить другой экземпляр этого же бота на своём или другом компьютере. |
| Туннель не подключается | Использовать `--protocol http2`, проверить интернет, VPN и блокировку исходящего TCP-порта 7844. |
| Телефон перестал открывать приложение после закрытия ноутбука | Проверить, что компьютер не уснул и все три процесса продолжают работать. |
